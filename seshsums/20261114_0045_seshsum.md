## The check pass, and what it changed
A read of the paper against the Lean sources found one gap in the main argument. The draft
compared the idealized model at n = 2^16 with the game at n = 8 and blamed the tree
idealization (short cycles) for the r = 0 discrepancy. That does not follow, and it took two
passes to get right.

First pass: the theory's fan effect depends on the size of the space; at n = 8 and 16 the
integer-diameter settings show none (`SHH.GD.no_fan_small`). Jeff asked why 64 would differ.
It does not: on a fine grid of μ the rise comes in gradually (first sliver near n = 24 at
r = 0, n = 55 at r = ½), and the whole-number grid had hidden that. `no_fan_small` stays, with
a docstring saying it covers those settings only.

Second pass, the one the paper now uses: **compare where the game starts.** A B-bit game has
n = 2^B states and starts as a hypercube, μ = B; learning only adds edges.

- At r = 0 the theory's rise always lies below μ = B (prototype, B = 3 to 24; exact at B = 4
  and 16, `SHH.GD.hypercube_start_falls`, new). So for the bit game the 1988 sentence "at
  r = 0 more edges reduce the time" is right; it is refuted only as a general statement, in
  sparse graphs (`SHH.GD.fan_pow2_zero`).
- At r = ½ the theory, from μ = B, also only improves, until about B = 20 (a 1% rise). The
  game has a fan effect at three bits (`SHH.BitGame.figure1_pattern_three`) and the 1988
  simulations showed one at five. So the walk does not explain the game's fan effect; what
  does is open.
- The 1988 Figure 2 used n = 10,000, where the pattern does appear, in sparse graphs.

Abstract, introduction, Sections 4 and 5, Table 3, Discussion, Limitations and Conclusion were
redrafted; CLAIMS T6–T10 rewritten to match.

Smaller corrections in the same pass:
- Eq. 5's proviso μ(1−r) ≫ 1 is stated; the r = 0 sentence of 1988 carries no proviso.
- "only from μ = 16 on do more edges help" was wrong: the peak at n = 2^16 is near μ = 6.
- The Heathcote sentence said diminishing relative returns is "what the data most clearly
  show"; Heathcote et al. argue the reverse for individual learners. Reworded.
- `curveGD_not_powerLaw` needs (1 + ε)·r < 1; the paper's "any exponent and tolerance" now
  says so.
- "32 operators that could be learned" are 32 start–goal pairs, 20 distinct new operators.
- Table 1's r = ½ column is certified exactly (`SHH.GD.fan_pow2_half_values`, new), so the
  uncertified 257 is gone. Also new: `SHH.GD.DOf_pow2_gen`.
- `tools/walk_check.py` prints the size dependence and the small-space values;
  `tools/bitgame.py` reports distinct operators.
