# The claims of Shrager, Hogg & Huberman (1988), and their status

Each claim the paper makes, restated, with its status in this repository. Status values:
**proved** (a theorem, named), **refuted** (a theorem contradicts it), **reinterpreted** (true
under a different statement, named), **supported numerically** (prototype only), **untested**.
Page numbers are the paper's. Kept current as the work proceeds.

## The theory (p. 416)

| # | Claim | Status |
|---|---|---|
| T1 | Eq. 1: a step toward the goal with probability P₋ = 1/(1 + (μ−1)(1−r)). | untested (definition `SHH.GD.pOf`; a consequence of idealizations I1–I2, not derived here) |
| T2 | Eq. 2: the expected steps s from distance D, "by standard techniques". | **proved** for the walk as stated: the closed form `SHH.Walk.s` solves the system (`SHH.Walk.term_sys`), the system has one solution (`SHH.Walk.sys_unique`), so `SHH.Walk.sys_eq_s`. The printed Eq. 2 (transcribed in `notes/equations.txt`) is exactly this function for every p ∉ {0, ½} (`SHH.Walk.eq2_printed`): the paper's formula is right. |
| T3 | Eq. 3: when P₋ > P₊, drift, s ≈ D/(P₋ − P₊). | **proved, sharpened**: `D/(2p−1) − 2p(1−p)/(2p−1)² ≤ s ≤ D/(2p−1)` (`SHH.Walk.drift_bounds`); Eq. 3 is the upper bound, off by at most a constant. |
| T4 | When P₊ = P₋, s = D². | **proved** (`SHH.Walk.s_half`). It fixes the boundary convention: forced reflection at D; the stay convention gives D² + D (`SHH.Walk.stay_half_sys`, `stay_half_value`). |
| T5 | Eq. 4: when P₊ > P₋, s grows exponentially with D. | **proved**: printed Eq. 4 is Eq. 2's exponential term, and `s` minus Eq. 4 is the term 2(p² + p(D−1) − D/2)/(2p−1)², linear in D (`SHH.Walk.eq4_remainder`). Exactly,  s = 2p(1−p)(((1−p)/p)^D − 1)/(1−2p)² − D/(1−2p). Also: s strictly increases with D for every 0 < p < 1 (`SHH.Walk.s_strictMono_D`). |
| T6 | Eq. 5: with a weak decision procedure and μ(1−r) ≫ 1, s ≈ (2n/μ)(1−r)^{ln n/ln μ − 1}. | **inexact where its conclusion is applied**: the step replaces (μ−1)^(D−1) by μ^(D−1) = n/μ; the omitted factor is ((μ−1)/μ)^(D−1) ≤ exp(−(D−1)/μ) (`SHH.GD.eq5_error_factor`, `SHH.GD.eq5_error_bound`), harmless under the stated proviso μ(1−r) ≫ 1 and far from one at small μ (≈ 0.05 at μ = 3, n = 10⁴). |
| T7 | "When r = 0, increasing the number of edges reduces the time to solve the problem." | **refuted as a general statement; true for the bit game.** In the paper's own idealized model, in sparse graphs: at n = 2¹⁶, r = 0, raising μ from 2 to 4 raises s from 256 to 9,824; by μ = 16 it is back down to 7,744 (`SHH.GD.fan_pow2_zero`, `SHH.GD.fan_pow2_worsens`; D exact by `SHH.GD.DOf_2_4` etc.; numerically the peak is near μ = 6). Numerically the same at n = 10⁴ (177 at μ = 2 → 2,468 at μ = 5). The rise lies outside Eq. 5's proviso μ(1−r) ≫ 1, but the r = 0 sentence carries no proviso. The rise comes in gradually with n (first sliver near n = 24, just above μ = 2; prototype, fine grid). **From the bit game's starting point it never occurs**: a B-bit game has n = 2^B and starts at μ = B, and from there s falls, exactly at B = 4 and B = 16 (`SHH.GD.hypercube_start_falls`) and numerically for every B from 3 to 24: the peak is always below μ = B. |
| T8 | With r > 0 but μ(1−r) ≫ 1, there is a range in which adding links increases s: the fan effect; "s will increase as links are added when \| **proved** for the first part at exact settings in sparse graphs: n = 2¹⁶, r = ½, μ 2 → 4 → 16 → 256 gives s ≈ 44.0 → 255.5 → 1117.75 → 257 (`SHH.GD.fan_pow2_half`, `SHH.GD.fan_pow2_half_values`); also inside the walk (`SHH.Walk.fan_witness_walk`, `fan_witness_half`). **Not from the bit game's starting point**: from μ = B, s falls at r = ½, exactly at B = 4 and B = 16 (`SHH.GD.hypercube_start_falls`), numerically for every B up to about 20, where a rise of about 1% first appears (3% at B = 24). The stated condition: untested (OPEN). |
| T9 | Eq. 6: with a strong decision procedure (r near 1), s ≈ ln n / ln μ, and "one obtains a power-law decay". | **reinterpreted, proved**: at r = 1, s = D exactly (`SHH.Walk.s_one`), so with μ linear in trials (condition C3) the curve is `SHH.GD.curveGD` = ln n / ln(μ₀ + ct). It improves (`curveGD_improves`) with strictly diminishing relative returns (`curveGD_diminishingRelative`), but for any ratio r and tolerance ε with (1+ε)r < 1 approximate scale invariance fails on long ranges (`curveGD_not_powerLaw`): the doubling ratio tends to 1. Numerically (n = 10⁴, μ₀ = 2, c = 1): within 12% of 7.41·t^{−0.29} over trials 1–100 (`tools/walk_check.py`). |
| T10 | Fig. 2: Eq. 2 "produces the range of behaviors observed in the bit game experiments" (improvement at r = 0 and 1, initial degradation at r = 0.5). | **does not hold from the game's starting point.** Fig. 2 used n = 10,000, where the walk shows the r = ½ fan effect in sparse graphs (and an r = 0 rise at small μ, T7). A B-bit game starts at μ = B; from there the idealized model falls at r = 0 and at r = ½ (`SHH.GD.hypercube_start_falls` at B = 4, 16; numerically at B = 3 and at B = 5, the simulations' size), while the three-bit game improves on average at r = 0 and worsens at r = ½ (`SHH.BitGame.figure1_pattern_three`). So theory and game agree at r = 0 and disagree at r = ½: the walk does not explain the game's fan effect. OPEN: what does; whether the five-bit game behaves like the three-bit one (milestone 3); a certificate at non-integer diameter, which the B = 3 and B = 5 comparisons need. |

## The simulations (pp. 414–415)

| # | Claim | Status |
|---|---|---|
| S1 | Fig. 1A, C (r = 0, 1): solution rates "consistent with the power law — approximately straight on a log-log plot" over trials 1–100. | improvement **proved** for one learning step on the three-bit game: the chunk `00?→11?` lowers the mean expected steps over all 56 games at r = 0 (58/7 → 2603/315) and r = 1 (12/7 → 23/14) (`SHH.BitGame.figure1_pattern_three`); the same for all 20 new single chunks (32 start–goal pairs) numerically (`tools/bitgame.py`). The curve's shape over 100 trials: milestone 3. |
| S2 | Fig. 1B (r = 0.5): performance initially degrades: the fan effect. | **proved** for one learning step on the three-bit game: the same chunk raises the mean expected steps at r = ½ (128/35 → ≈3.682) (`SHH.BitGame.figure1_pattern_three`); all 20 new single chunks do so numerically. Also per game: `SHH.BitGame.chunk_slows_game` (game 000→001 slows at r = 0 and r = ½). |
| S3 | At r = 1 the heuristic "comes very close to the optimal path". | **proved for the initial operators**, for every number of bits: every move the r = 1 procedure can make is one bit closer to the goal (`SHH.BitGame.r1_moves_closer`), so every run takes exactly the Hamming distance. With learned operators, an exception: with the chunk `0000→1111` on the four-bit game, game 0001→1110 takes 15/4 expected steps at r = 1 against a shortest path of 3 (`SHH.BitGame.greedy_not_optimal`, `three_step_path`); the paper says only "approximates", so this confirms rather than refutes it. |
| S4 | The learned operator "connects two pairs of states", i.e. adds 2 edges for one don't-care bit (2^k for k). | **proved** for the paper's example (`SHH.BitGame.chunk_paper`, `chunk_paper_applies`); in general a chunk takes its start to its goal (`SHH.BitGame.chunk_apply`). |
